MAJOR CASE STUDY #1 • HEALTHCARE ARCHITECTURE

HelixCare — Microservices Healthcare Platform

A scalable microservices-based healthcare backend that supports patient onboarding, automatic billing account creation, and asynchronous analytics processing.

Problem Statement

Legacy monolithic healthcare backends experience severe performance degradation and risk data corruption when patient registration, billing creation, and analytics logging execute synchronously on a single database.

Engineered Solution & Flow

Architected a decoupled microservices backend with Spring Cloud API Gateway (Port 4004) routing `/auth/**` to Auth Service (Port 4005) and `/api/patients/**` with JWT validation to Patient Service (Port 4000). Utilizes synchronous gRPC (Port 9001) for instant billing creation and Apache Kafka event streams for asynchronous analytics processing.

HELIXCARE — SYSTEM ARCHITECTURE FLOW Exact Production Workflow

API Gateway 4004 — Entry point, request routing & JWT validation filter
Auth Service 4005 — Authentication, JWT generation & `/validate` token verification
Patient Service 4000 — Patient management, token validation & publishing patient events
Billing Service 4001 9001 Instant billing account creation via synchronous gRPC
Analytics Service — — Kafka consumer processing patient events & generating analytics
Kafka (Message Broker) 9092 (Default) — Event streaming broker for asynchronous `patient` topic
